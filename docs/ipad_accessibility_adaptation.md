# iPad Landscape & Accessibility Adaptation (May 2026)

This document details the architectural and UI changes implemented to support iPad landscape orientation and enhance the application's accessibility for users who prefer large fonts and buttons.

## 1. Orientation & Layout Strategy

The application now uses a hybrid responsive strategy to adapt between iPhone (Portrait/Landscape) and iPad (Portrait/Landscape).

### Detection Logic
We combine SwiftUI's Environment variables and `GeometryReader` to determine the best layout:
*   **`isPad`**: Detected via `@Environment(\.horizontalSizeClass) == .regular && @Environment(\.verticalSizeClass) == .regular`.
*   **`isLandscape`**: Detected via `GeometryReader` by comparing `width > height`.

### Collapsible Sidebar Navigation Rail (iPad Landscape)
In iPad landscape mode, the standard bottom tab bar is replaced with a **Collapsible Vertical Navigation Rail** on the left side of the screen.
*   **Compact Mode (Default)**: Occupies only 100pt of width and shows only primary icons (`waveform`, `sparkles`). This maximizes horizontal space for the main content.
*   **Expanded Mode**: Triggered by tapping the menu icon (three horizontal lines). Expands to 220pt width and reveals full text labels with smooth spring animations.
*   **Implementation**: A `VStack` with dynamic width and conditional text visibility based on `@State private var isRailExpanded`.
*   **Benefits**: Provides a clean, minimalist interface by default while maintaining accessibility via 1-tap expansion for users who need text labels.

## 3. Smart Speak (AAC) Optimization

The AAC Expander view was redesigned for the 2-column iPad landscape layout.

### Multi-Column Results
In landscape, the AAC view splits into:
*   **Left Column (600pt)**: Controls, Shorthand Display, and Quick Chips.
*   **Right Column (Flexible)**: Scrollable list of expanded options generated by Gemma.

### Quick Chip "Communication Board" (Adaptive Grid)
*   **Problem**: Small capsule-style chips and horizontal scrolling were difficult for users to navigate precisely.
*   **Solution**: Redesigned Quick Chips into a structured **Tile Board** using a `LazyVGrid` across all orientations.
*   **Tile Design**: Each shortcut is now a large rectangular tile with a prominent emoji on top and bold text below.
*   **Ergonomics**: 
    *   **Eliminated Scrolling**: Horizontal scrolling is replaced by a vertical grid, which is more natural for thumb/finger movement.
    *   **Large Hit Targets**: Increased tile sizes (minimum 140pt on iPad, 90pt on iPhone) with 10-12pt spacing.
    *   **Visual Clarity**: Distinct borders and tinted backgrounds provide a "soundboard" feel, reducing cognitive load.
*   **Layout Protection**: On iPhone, the grid is height-constrained to 160pt to ensure that AI-generated results remain visible immediately upon selection.

## 4. Implementation Details

### ContentView.swift
The `body` was refactored into a `GeometryReader` block that switches between the `useRail` (HStack) and `standard` (ZStack) layouts.

### AACExpanderView.swift
The `quickChipsView` now uses a `Group` with a conditional check:
```swift
if isPad && isLandscape {
    ScrollView {
        LazyVGrid(columns: [GridItem(.adaptive(minimum: 180), spacing: 15)], spacing: 15) {
            // ...
        }
    }
} else {
    ScrollView(.horizontal) {
        // ...
    }
}
```

### Visual Polish
*   **Shadows**: Increased shadow radius on large buttons (up to 15pt) to provide better depth and visual separation.
*   **Corner Radii**: Increased to 24pt for large containers to match the modern "soft" aesthetic of the up-scaled UI.

## 5. Dynamic Content & Management

### User-Editable Quick Chips
The application has transitioned from hardcoded shortcuts to a fully dynamic system managed by `QuickChipManager`.
*   **Persistence**: Chips are stored as `Codable` structs in `UserDefaults`, allowing users to maintain their custom shorthand library across sessions.
*   **Management UI**: A "Smart Speak Shortcuts" section in Settings allows users to:
    *   **Edit**: Tap and rename any existing chip in-place.
    *   **Add**: Create new custom shortcuts with emojis and text.
    *   **Delete**: Explicitly remove chips using the **Red Trash Icon** (replacing swipe-to-delete for better accessibility).

### Shorthand Input Refinements
To accommodate longer phrases and improve readability:
*   **Increased Height**: The shorthand box now has a `minHeight` (140pt on iPad) to show multiple lines of text.
*   **Balanced Scaling**: The font size was slightly reduced (from 48pt to 38pt on iPad) to fit more words while maintaining high visibility.
*   **Top Alignment**: Content now starts from the top-left, following standard text-entry conventions.

## 6. Keyboard Handling & Landscape Editing

To prevent the software keyboard from obscuring critical content in landscape mode, especially on smaller iPads or iPhones, a "Focus Editing" mode was implemented for transcriptions.

### Intelligent UI Culling
When the user enters editing mode (`transcriptionVM.isEditing == true`), the UI dynamically Cullls non-essential elements:
*   **Hidden Elements**: Branding headers, navigation tabs (bottom bar), statistics sections, and primary action buttons (Record/Clear/Copy/Share).
*   **Vertical Space Reclamation**: The 100-140pt bottom padding reserved for the navigation bar is reduced to 0pt.
*   **Minimized Spacing**: Vertical spacing between remaining elements is reduced to 5pt.

### Safe Area & Keyboard Respect
*   **Safe Area Logic**: Transitioned to `.ignoresSafeArea(.container, edges: .bottom)`. This ensures that while the background/tab bar can bleed into the bottom safe area normally, the **Keyboard Safe Area** is explicitly respected, forcing the ScrollView and TextEditor to move up when the keyboard appears.
*   **Layout Priority**: The ScrollView containing the text editor is given `.layoutPriority(1)` to ensure it consumes all available reclaimed space.

### Cancel & Safety Controls
*   **Explicit Cancel**: Added a prominent "Cancel" button to both the keyboard toolbar and the bottom action row. This allows users to exit the focused editing mode and restore the original transcription if they make a mistake during correction.
*   **Visual Focus**: In landscape editing, the text area expands to the full width of the screen (removing horizontal margins and corner radii) to provide a typewriter-like focused experience.
