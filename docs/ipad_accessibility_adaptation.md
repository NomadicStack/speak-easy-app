# iPad Landscape & Accessibility Adaptation (May 2026)

This document details the architectural and UI changes implemented to support iPad landscape orientation and enhance the application's accessibility for users who prefer large fonts and buttons.

## 1. Orientation & Layout Strategy

The application now uses a hybrid responsive strategy to adapt between iPhone (Portrait/Landscape) and iPad (Portrait/Landscape).

### Detection Logic
We combine SwiftUI's Environment variables and `GeometryReader` to determine the best layout:
*   **`isPad`**: Detected via `@Environment(\.horizontalSizeClass) == .regular && @Environment(\.verticalSizeClass) == .regular`.
*   **`isLandscape`**: Detected via `GeometryReader` by comparing `width > height`.

### Sidebar Navigation Rail (iPad Landscape)
In iPad landscape mode, the standard bottom tab bar is replaced with a **Vertical Navigation Rail** on the left side of the screen.
*   **Implementation**: A `HStack` containing the Navigation Rail (width 200pt) and the main content area.
*   **Benefits**: Reduces vertical thumb travel on wide screens and keeps primary navigation accessible while seated or using a stand.

## 2. Accessibility-First UI Scaling

Following user feedback, the UI has been "up-scaled" significantly to support users with motor or visual impairments.

### Typography Scaling
| Element | Device/Orientation | Font Size / Style |
| :--- | :--- | :--- |
| **Transcription Text** | iPad Landscape | 64pt Bold |
| **Transcription Text** | iPad Portrait | 72pt Bold |
| **Transcription Text** | iPhone | 40pt Bold |
| **AAC Sorthand** | iPad | 48pt Bold |
| **AAC Option Buttons** | iPad | 34pt Bold |

### Button & Touch Target Scaling
| Element | Device | Size (Diameter/Width) |
| :--- | :--- | :--- |
| **Record Button** | iPad | 180pt |
| **Record Button** | iPhone | 110pt |
| **Clear Button** | iPad | 120pt |
| **Clear Button** | iPhone | 80pt |
| **Navigation Icons** | iPad | 44pt Bold |

## 3. Smart Speak (AAC) Optimization

The AAC Expander view was redesigned for the 2-column iPad landscape layout.

### Multi-Column Results
In landscape, the AAC view splits into:
*   **Left Column (450pt)**: Controls, Shorthand Display, and Quick Chips.
*   **Right Column (Flexible)**: Scrollable list of expanded options generated by Gemma.

### Wrapping Quick Chips (Adaptive Grid)
*   **Problem**: A horizontal scroll view for "Quick Chips" is inefficient in landscape as it wastes vertical space and hides options.
*   **Solution**: Implemented a `LazyVGrid` with `adaptive` columns (`minimum: 180pt`).
*   **Behavior**: Chips wrap to new lines automatically, ensuring all 1-tap options are visible simultaneously without scrolling.

## 4. Implementation Details

### ContentView.swift
The `body` was refactored into a `GeometryReader` block that switches between the `useRail` (HStack) and `standard` (ZStack) layouts.

### AACExpanderView.swift
The `quickChipsView` now uses a `Group` with a conditional check:
```swift
if isPad && isLandscape {
    LazyVGrid(columns: [GridItem(.adaptive(minimum: 180), spacing: 15)], spacing: 15) {
        // ...
    }
} else {
    ScrollView(.horizontal) {
        // ...
    }
}
```

### Visual Polish
*   **Shadows**: Increased shadow radius on large buttons (up to 15pt) to provide better depth and visual separation.
*   **Corner Radii**: Increased to 24pt for large containers to match the modern "soft" aesthetic of the up-scaled UI.
